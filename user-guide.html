Orientation for new users

Finding your way around the Web Apps

This isn't one application — it's a family of independent tools that all read and write the same project data. Once you know which tool owns which job, moving between them is quick.

The big picture

Every app below is a plain, self-contained website — no login wall in common, no shared menu bar. What ties them together is one shared database of projects sitting behind the scenes.

  • Intake is where a new project idea first gets logged and triaged.
  • Roadmap is the master timeline — the source of truth most other apps read from.
  • Schedule A plans who is allocated to what, week by week.
  • Project List and Comparison are read-oriented views built on top of Roadmap and Schedule A.
  • DevOps Visualiser stands alone — a CSV-in, diagram-out tool with no login and no shared data.

Getting in

Every app except DevOps Visualiser checks who you are before showing anything. Access is granted per app, at two levels.

No access

You can reach the page but see a sign-in / access-denied screen. Ask whoever manages Admin to grant you a role.

Viewer

You can open the app and see all its data — boards, timelines, dashboards — but can't change anything.

Editor

Full read/write for that app: create, drag, edit, delete. Comparison needs editor on two apps to matter, since it's read-only itself.

Access is granted separately for Intake, Roadmap, and Schedule A — being a viewer of one doesn't carry over to the others. Project List piggybacks on Roadmap access, and Comparison needs both Roadmap and Schedule A.

How it fits together

Everything hangs off one shared registry of projects. A project can be born in Intake, tracked on the Roadmap, and staffed in Schedule A — and the read-only apps stitch those views back together.

Solid boxes read from or write to the shared registry. Dashed boxes sit outside that system entirely.

The apps, one by one

Each entry below covers what the app is for, what access you need, and the steps for the task you'll reach for most.

Intake

Intake Tracker — where new project requests come in
Requires: Intake viewer

A kanban board that carries a request from first ask through triage to prioritisation, plus dashboards for KPIs and priority scoring (Strategic / Operational / Customer / Commercial).

Pages
  • index.html — the board
  • kpis.html / intake-full-kpis.html — dashboards
  • priority.html — scoring view
Links out to The shared projects registry, via the "find or create project" picker

Log a new request

  1. On the board, click + New request in the top toolbar (editor access only — it's hidden for viewers).
  2. Fill in the request details, then link it to a project via the picker, or create a new one.
  3. The request information panel opens with details to be completed or edited when the request/project is active.
  4. The card lands in the first column; drag it across columns as it moves through triage.

Roadmap

Technology Roadmap — the master planning timeline
Requires: roadmap-db viewer

The Gantt-style planner most other apps ultimately read from. Drag and resize project bars across a timeline, tag phase / health / team, and switch between week, month, and quarter views.

Pages
  • index.html — main planner
  • releases.html — feature-release timeline
  • roadmap-view.html — static exported snapshot, no login
Links out to The shared projects registry, via the same picker Intake uses

Add a project to the timeline

  1. Click + Project top-right (editor access — this and Auto Sort, Export, and Data Clean Up are disabled for viewers).
  2. Link it to a project in the registry, or create one, then set its start dates and duration.
  3. Drag the bar to move it, or drag its edges to resize; click a bars phase icon to open Edit Project for phase, health, team, and other project settings.
  4. Use Display to change label style, row density, or switch between light and dark, and the Week / Month / Quarter toggle to change zoom level.
  5. Use Filtersto reduce the project list.

Schedule A

Resource Planner — who's allocated to what, week by week
Requires: schedule-a-db-v2 viewer

A capacity-planning Gantt chart over a rolling 26-week window, showing which people or roles are committed to which projects.

Pages
  • index.html — single page
Links out to The projects registry, via its own search box (not the shared picker)

Allocate someone to a project

  1. Switch to Projects or Resources view depending on how you want to browse.
  2. Open the row for the project or person, then Add resource to place a new allocation bar — it defaults to a one-week span.
  3. Drag the bar's edges to stretch the allocation; use Assign Role first if the role you need isn't listed yet.
  4. Sort A-Z / Sort Date and the zoom controls help when the sheet gets busy; Back Up Data exports everything.
  5. Selecting a week from the time line will open the resource overview panel.

Project List

Open Projects List — a live, sortable table
Requires: roadmap-db viewer

The fastest way to see every open project at a glance — health, phase, title, planned start date — sourced live from Roadmap's own data. It has no data of its own.

Pages
  • index.html — editable list
  • view.html — read-only, shareable variant
Depends on Roadmap's tables directly — no separate access key of its own

Share the list with someone outside the team

  1. Sort or filter the table on index.html until it shows what you want.
  2. Use the CSV export for a static snapshot, or send the view.html link for a live read-only page.

Comparison

Roadmap vs Schedule Comparison — spot the conflicts
Requires: roadmap-db AND schedule-a-db-v2 viewer

Overlays the Roadmap timeline and Schedule A's resourcing bars on one shared axis, so you can see at a glance where committed dates and available capacity don't line up. The only app needing two separate permissions.

Pages
  • index.html — single page
Depends on Both Roadmap's and Schedule A's data — nothing of its own

Check a project for resourcing conflicts

  1. Open the app — if you're missing either underlying permission, you'll see an access notice instead of data.
  2. Find the project on the shared timeline; its Roadmap bar and Schedule A bars sit stacked on the same weeks.
  3. A gap between committed dates and staffed weeks is your conflict signal — flag it back to whoever owns Schedule A.

DevOps Visualiser

Azure DevOps Work-Item Visualiser
No login needed

A standalone tool with no database connection at all. Drop in a CSV export from Azure DevOps and it draws a hierarchical Epic → Feature → Element → Task diagram, with filters and an export-to-standalone-HTML option.

Visualise a DevOps export

  1. Export your work items from Azure DevOps as CSV.
  2. Open the app and load that CSV — everything happens locally in your browser.
  3. Use the filters to narrow the hierarchy, then export to a standalone HTML file if you want to share the diagram without sharing the tool.

Gantt Charts

Simple gantt chart maker
Shared (team) and standalone version

Depite a project timeline and activities with a simple gantt chart. Options for milestones and headline (summary} task, colour, and tags. Charts can be exported to use in other application.

Shared
  • Projects stored in a database
Standalone Create and save projects locally (only in Edge or Chrome)

Open or create a new project

  1. Add new tasks and move the bar around to the date needed, stretch or shorten for the desired duration.
  2. Click the status symbol (initially an empty circle) to change bar settings; date, time, tag, status and colour.
  3. Day|Week|Month, Zoom, and Display button can change how the page looks.
